# Dashboard information hierarchy audit — 2026-03-10

范围：`crossborder-risk-radar` dashboard v1 首页信息架构。
基于：`runtime/latest_rendered.txt` 与近期 `runtime/runs/*` 输出。
目标：只定义首页该留什么、该下沉什么，不改抓取逻辑。

## 结论先说

首页应该只回答 4 件事：
1. **今天最重要的风险是什么**
2. **有哪 2-3 条事件值得先看**
3. **今天先做什么 / 继续观察什么**
4. **如果和我更相关，去哪里深挖**

现在的输出问题不是信息不够，而是**首页塞进了太多“解释层”和“分层动作细节”**，导致用户第一屏读完还没进入决策。

## 首页保留

### 1. 总览
保留最小字段：
- 一句话结论
- 头号信号
- 今日最值得看（top 1 event）
- 首页提醒 / 暂缓动作（二选一，别重复）

### 2. 事件卡（最多 3 张）
每张卡只保留：
- 事件标题
- 风险判断（risk level / region / topic）
- 为什么排这里（一句话）
- 当前首页先做（1 条）
- 接着盯（1 条）
- 深挖入口：查看高相关画像 / 查看事件详情

### 3. 动作摘要
保留两组聚合：
- 今日先做（最多 3 条）
- 继续观察（最多 3 条）

### 4. 筛选 / 深挖提示
保留极短提示：
- 可按市场 / topic / 履约模式筛选
- 若某条事件高相关，再切到画像深挖

## 首页下沉为“深挖信息”

以下内容不适合首页默认展开，应进入事件详情页 / 画像页：
- `适用性分层` 全量展开
- `高相关是谁 / 中相关是谁 / 低相关/观察是谁`
- `各层该做什么` 的多段动作清单
- `当前视角适用性` 这类解释字段
- `为什么值得所有卖家知道 / 经营含义` 的长解释
- `优先级解释` 整段列表
- 长版 `按画像深挖` 说明文案
- 来源明细（首页卡片里只保留来源数量或可信度即可；完整 source 放详情）

## 产品判断

### 首页最该保留
- **事件级排序 + 每条事件的单条动作建议**
- 也就是：`先看什么` + `先做什么`

### 首页最该砍掉
- **适用性分层与各层动作的整块展开**
- 这部分信息密度高、解释味重，适合在用户点进某条事件后再给，不该压在首页第一层。
