# Dashboard UI v1 spec（超短版）— 2026-03-10

范围：`crossborder-risk-radar` 首页 / dashboard UI v1。
目的：约束首页最小形态，避免做成“信息很多但第一眼看不懂”的大杂烩。
基于：`runtime/latest_rendered.txt` 当前输出形态做产品/交互审计；未发现独立前端页面实现，因此本轮以首页信息架构与可扫读性为准。

## v1 首页必须有

### 1. 顶部总览区（第一屏必须出现）
只留 4 个东西：
- 一句话结论
- 头号信号（Top 1 risk）
- 今日最值得看（Top 1 event）
- 一个明确按钮/入口：`看事件详情` 或 `按画像深挖`

### 2. 事件卡区（最多 3 张）
每张卡只留：
- 标题
- 风险标签：`topic + risk level + region`
- 为什么排这里（一句话）
- 今天先做（1 条）
- 继续观察（1 条）
- 深挖入口

### 3. 动作摘要区
只做两组聚合：
- 今日先做（最多 3 条）
- 继续观察（最多 3 条）

### 4. 筛选区
v1 只保留 3 个筛选维度：
- 市场
- topic
- 履约路径

## v1 首页不要做

先别上这些：
- 首页展开完整 applicability layers
- 首页展开“高相关 / 中相关 / 低相关”整段解释
- 首页展示每条事件的长版经营含义
- 首页展示分履约动作全量清单
- 首页堆 source 明细、ranking 解释、方法论说明
- 图表大盘、趋势折线、复杂热力图、可配置 widget
- 默认绑定某个平台画像当首页主视角

一句话：**首页只负责“先看什么、先做什么”，不负责把所有解释一次讲完。**

## 推荐布局（手机优先）
1. 顶部摘要卡
2. Top 3 事件卡（纵向单列）
3. 今日先做 / 继续观察（双 section，仍纵向）
4. 筛选入口
5. 深挖入口

要求：
- 手机首屏要在不滚太多的情况下看见“结论 + Top 1 + 第一张事件卡”
- 单张卡尽量控制在 5~6 行核心信息内
- 同一层不要同时出现两个差不多意思的模块（比如“头号信号”和“今日最值得看”写成两大段重复文案）

## 对当前实现结果的审计

当前能拿到的是 `runtime/latest_rendered.txt`，不是独立前端页面，但已经足够看出首页层级。

### 当前做对了
- 已经有事件排序意识，方向对
- 已经把“今日先做 / 继续观察”单独拎出来，方向对
- 已经避免默认站死某个单一平台画像，方向对

### 当前最影响“一眼看懂”的问题
- 首页块太多：`打开深挖 / 优先级解释 / 按画像深挖 / 暂缓动作 / 一句话结论` 同层堆叠，阅读阻力偏大
- 事件卡里“高相关是谁”信息太长，像解释层，不像首页卡片
- `优先级解释` 更像详情页内容，不该放首页核心流里
- `分履约动作` 适合二级页，不适合首页默认展开

### 是否满足“手机也能扫”
结论：**还没完全满足。**
原因不是内容错，而是首页解释层偏厚，第一屏还不够狠。

## 最小验收标准（主实现别跑偏）
- 用户 3 秒内能回答：今天先看哪条
- 用户 10 秒内能回答：我现在先做哪 1~3 件事
- 手机端不需要理解完整方法论，也能完成一次扫读
- 点开单条事件后，才看到 applicability / 分履约动作 / source 明细

## 最终判断

### UI 首页最该保留什么
- **事件优先级排序 + 每条事件只给一条立刻可执行动作**

### UI 首页最该避免什么
- **把首页做成解释文档：层层说明、块块都想留，结果第一眼没有主次**
