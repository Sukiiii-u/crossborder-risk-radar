# Dashboard UI v2 审计结论（入口式首页）

## 结论先说
当前 UI v1 **不符合**“几个大板块，想了解什么自己点进去”的目标。

原因不是丑，是 **首页信息层级太深**：
- 首页同时塞了 summary、头号信号、事件卡片、展开详情
- 单张卡片在首页就暴露了过多字段：高相关画像、动作、为什么排这里、适用性分层、来源
- 用户还没决定“想看什么”，首页就已经开始逼用户读细节

它更像 **浓缩版分析工作台**，不是 **大板块入口式首页**。

---

## UI v2 首页最小交互层级
首页只保留 **1 层入口 + 1 层轻摘要**。

### 首页只放 4 个大板块
1. **今日总判断**
   - 显示 2~3 行
   - 只回答：今天整体风险高不高、最该先盯哪一类、一句总建议

2. **需要先看什么**
   - 显示 3 行以内
   - 只放 Top 3 入口卡：如物流 / 税务 / 平台规则
   - 每张卡只显示：类别、风险级别、1 句 why it matters

3. **谁最该点进去看**
   - 显示 2~3 行
   - 只放 3 个画像入口：跨境直发 / 平台仓履约 / 3PL/商家仓
   - 每个入口只显示：你今天是否高相关 + 1 句提醒

4. **今天先做**
   - 显示 3 行
   - 只保留 3 条 today actions
   - 不解释推理过程，不展开事件归因

---

## 什么必须隐藏到详情页
以下内容 **不要在首页展开**，统一藏到详情页：
- 完整事件卡列表
- 为什么排这里 / 为什么先看 的长解释
- applicability layers 全量分层
- sources / 链接列表
- region、risk type distribution、metadata
- 多段 seller reasoning
- 任何超过 1 句话的动作解释

一句话：**首页给判断和入口，详情页才给证据和展开。**

---

## 详情页建议分成 2 种
### A. 风险类别详情页
适合从“物流 / 税务 / 合规 / 平台规则”点进去
- 顶部：该类别今天一句判断
- 中部：相关事件列表（每条再展开）
- 底部：来源与证据

### B. 卖家画像详情页
适合从“跨境直发 / 平台仓 / 3PL”点进去
- 顶部：该画像今天最受影响的 1~2 件事
- 中部：按事件给动作建议
- 底部：观察项 / 暂时不用做的事

---

## 对当前实现的审计
### 符合的部分
- 已有“头号信号”概念，说明团队知道首页需要主叙事
- 事件卡支持展开，说明已有详情层雏形
- 卡片里已经有 `一句话动作`，这是对的

### 不符合的部分
- 首页仍然以“事件卡列表”作为主结构，不是“大板块入口”
- 第一屏可读字段太多，读起来还是密密麻麻
- 用户需要在首页处理过多分析文本，而不是先选方向
- `适用性分层 / 来源 / 为什么排这里` 出现在首页展开层，仍然过早
- summary 区块里“风险类型分布”价值低，抢了首页注意力

---

## v2 首页保留 / 隐藏原则
### 最该保留
- **今日总判断**
- **Top 3 风险类别入口**
- **Top 3 卖家画像入口**
- **3 条今天先做**

### 最该隐藏
- **完整事件细节**
- **适用性分层长文**
- **来源列表**
- **排序解释 / 推理解释 / 各种 metadata**

> 首页像商场导览牌，不像仓库盘点表。
