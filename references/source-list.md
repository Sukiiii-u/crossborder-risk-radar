# Crossborder Risk Radar v2 Source List

> 目标：不是把源堆满，而是补一批**官方且对卖家经营判断更有动作价值**的信号。v2 继续保持少而精：平台规则、海关/税务、物流履约、卖家行业媒体，四类都要有，但不追求全覆盖。

## 当前保留 / 采用的来源组合

### 1. EcommerceBytes
- 类型：平台 / 卖家行业媒体
- 作用：追 Amazon / eBay / Etsy 等平台侧的卖家政策、费用、国际物流与账号相关变化
- 保留原因：叙事本来就贴卖家经营语境，适合补“平台动作对卖家有什么影响”
- 备注：仍然是最容易带噪的媒体源，所以继续靠关键词和排噪词强约束

### 2. Digital Commerce 360
- 类型：电商行业媒体
- 作用：补 tariff、delivery、marketplace、物流成本变化等经营层信号
- 保留原因：能补一些卖家经营层面的成本和平台变化，但仍需防止宏观企业新闻占位过高

### 3. FreightWaves
- 类型：物流 / 供应链媒体
- 作用：识别航运、港口、附加费、区域运输中断、仓储与履约压力
- 保留原因：物流仍是跨境卖家的核心风险面之一，且这一源的运输中断/附加费类信号质量较高

### 4. CBP Newsroom
- 类型：官方 / 政策源
- 作用：补美国海关、ACE、报关、trade notice、duty / tariff / de minimis 等执行层变化
- 保留原因：更接近卖家/报关/货代会真的碰到的执行层信号，而不是大而空的宏观口号

### 5. EU Taxation and Customs Union News
- 类型：官方 / 政策源
- 作用：补欧盟 VAT、customs、ICS2、Combined Nomenclature、进口与电商包裹规则相关更新
- 新增原因：这类变化会直接影响中国卖家做欧盟直邮、低申报、税务申报、清关与品类定价判断；官方源的动作价值明显高于泛欧盟新闻
- 接入方式：使用公开 RSS `https://taxation-customs.ec.europa.eu/node/2/rss_en`

### 6. Amazon Seller Forums - News and Announcements
- 类型：官方 / 平台公告源
- 作用：补 Amazon 官方面对卖家的 fee、policy、compliance、listing requirements、global selling、FBA 规则更新
- 新增原因：比二手媒体转述更早，也更接近卖家需要立即判断的“平台动作”
- 接入方式：当前没有稳定公开 RSS，因此只做了**最小 HTML 列表解析兼容**，限定在公开的 `News and Announcements` 分类页，不碰登录态页面和复杂站内抓取

## 本轮明确拒绝的候选源

### 拒绝：TikTok Shop Seller Policy / Policy Pulse（本轮未接入）
- 原因 1：公开页面强客户端渲染，当前没找到稳定、公开、可长期依赖的 RSS / Atom / sitemap 级结构化入口
- 原因 2：如果硬上，就要为单一来源引入更重的页面抓取或站内接口逆向，不符合这轮“只做最小兼容层、不大改抓取框架”的约束
- 原因 3：相比之下，EU TAXUD 和 Amazon 官方公告页的信号密度 / 落地成本比更高，优先级更合理
- 结论：**先拒绝，不是假装支持。**后续若确认到稳定公开 feed 或可复用的轻量列表接口，再补

### 拒绝：Amazon 中国站政策页（本轮未接入）
- 原因 1：目前更像静态帮助/政策文档集合，不是持续更新的公开 feed 型来源
- 原因 2：如果直接抓静态政策页，很容易变成“常驻文档爬虫”，而不是风险雷达的增量信号源
- 结论：除非后续确认到明确的公告流 / 更新流，否则先不加

### 拒绝：额外中文宏观政策源（本轮未接入）
- 原因：这轮目标不是扩新闻面，而是补更贴卖家动作判断的官方信号；宏观中文新闻源很容易把雷达重新带回“大新闻摘要器”
- 结论：宁可少，不为了中文覆盖硬加

## 当前 v2 的来源结构意图

现在这组 source 强调 6 个视角：
1. **平台卖家媒体视角**：EcommerceBytes
2. **电商经营媒体视角**：Digital Commerce 360
3. **物流履约视角**：FreightWaves
4. **美国海关合规视角**：CBP Newsroom
5. **欧盟税务与海关视角**：EU Taxation and Customs Union News
6. **Amazon 官方平台公告视角**：Amazon Seller Forums - News and Announcements

## 新增的来源元数据约束

每个 source 现在除了 `topic`，还必须声明两类 ranking 元数据：

1. `trust_tier`
- `official`：政府 / 海关 / 欧盟税关等官方源
- `platform-official`：平台官方卖家公告 / 论坛公告
- `industry`：卖家行业媒体、物流行业媒体
- `media`：泛媒体或较弱的资讯型源

2. `seller_signal_bias`
- `high`：天然更接近卖家动作判断
- `medium`：有用，但需要更多过滤
- `low`：更偏资讯背景，只能做补充

目的不是美化配置，而是把“这个源值不值得信”以及“它离卖家动作有多近”显式写进配置层，避免 ranking 继续靠硬编码猜。

这样抓出来的内容，会更像：
- 平台费用 / 规则 / 列表要求变化
- 美国与欧盟海关/税务执行变化
- 国际物流中断或附加费
- 直接影响卖家履约、利润、定价、站点布局与合规动作的信号

而不是：
- 泛国际新闻
- 纯宏观贸易表态
- 与卖家动作关系很弱的泛行业资讯

## 选源原则（继续沿用）
1. 先高相关，再高覆盖。
2. 先公开可访问，再考虑复杂接入。
3. 先能支撑“风险判断 + 动作建议”，再考虑资讯丰富度。
4. 同类来源只留 1–2 个代表，不堆多。
5. 平台 / 行业 / 政策 / 物流 四类至少要有基本覆盖。
6. 如果一个候选源需要单独发明一套抓取框架，先拒绝，别把 source 层做成爬虫项目。

## 一句话结论

v2 不是“多加几个站”，而是把**EU 官方税关信号**和 **Amazon 官方卖家公告信号**补进来；TikTok 这次没硬上，是因为不想为了凑数把抓取层搞脏。
