# 产品逻辑 v2

## 核心结论
`跨境风险雷达` 不能只做 analyze，也不能只做抓取。

正确结构是：
1. **Capture**：抓取 / 汇总外部风险信号
2. **Brief**：把外部变化压成高价值风险卡片
3. **Analyze**：翻译成卖家经营影响
4. **Action**：输出优先级明确的动作建议

## 哪一层是差异化核心
真正的差异化不在抓取本身，而在：
- 固定的跨境卖家视角
- 不同 seller profile 的影响映射
- 更具体的经营动作建议

## 为什么用户不能直接问通用 AI 替代
如果只是“分析这条新闻”，用户当然可以直接问别的 AI。
这个产品要成立，必须做到：
- 同一事件对不同卖家画像给不同判断
- 输出能进入卖家待办清单
- 明确哪些动作现在做，哪些本周做，哪些只监控

## 最小可成立版本
### 入口层
- 少量高价值来源
- 少量高价值事件
- 轻量 brief

### 核心层
- 影响面固定框架
- 动作模板
- 紧急程度分层

### 当前实现顺序
1. 先改 contract
2. 再补 seller profile / risk taxonomy / action templates
3. 再调整 examples 和 tests
4. 最后补最小抓取 / brief 入口
